# RIVET 确定性交易后端原型：v0 业务规则

版本：0.1
日期：2026-07-29
性质：技术演示规范，全部品牌、客户、订单、物流和政策均为合成数据。

## 1. 目标与边界

v0 只实现鞋服电商线上售后的确定性后端：身份验证、订单与物流查询、政策查询、取消订单、退货申请、尺码换货申请和转人工。它不是端到端客服 Agent，也不是已经闭合全部安全边界的生产交易层。

v0 不处理真实支付、自动退款、赔偿金额、平台 API、图片质检、语音客服、多 Agent、跨会话长期记忆或真实个人数据。

系统的责任划分是：

- 未来的大模型负责理解自然语言、识别意图、补齐缺失参数和组织回复，只能调用导出的 10 个 Agent 工具。
- 宿主应用负责认证、注入客户与会话身份、展示预览、记录可信确认并触发执行；这些能力不在 Agent 工具 Schema 中。
- 确定性代码负责身份、数据权限、资格判断、状态转换、幂等、库存和最终写入。
- 人工客服负责瑕疵、破损、错发、责任争议、政策歧义和自动流程无法安全判断的情况。

## 2. 不可破坏的业务不变量

1. 客户身份由服务端认证会话确定，模型不能传入或改写 `customer_id`。
2. 客户只能读取自己的订单。对他人订单统一返回“未找到”，不泄露订单是否存在。
3. 订单、物流、库存和售后状态只能来自结构化工具，模型不得猜测。
4. 高影响交易写操作必须经过 `prepare → 宿主展示 → 可信确认 → execute`。
5. `prepare` 不得修改订单、库存或创建售后单。
6. 确认事件必须绑定客户、会话、审批、预览哈希、宿主 UI 事件和确认来源。
7. `execute` 必须校验客户、会话、审批状态、有效期、订单版本、确认事件和执行前资格。
8. 模型提供的布尔值、幂等键或自然语言自我判断不能构成可信确认。
9. 网络超时后不得创建新审批盲目重试；同一 `approval_id` 的重放应只返回首次执行结果。
10. 知识库文本只是资料，不能覆盖系统规则，也不能直接触发工具。
11. 工具失败时不得对用户宣称成功。

## 3. 订单状态机

```text
PAID ────────→ PROCESSING ────────→ SHIPPED ────────→ DELIVERED
  │                 │
  └──→ CANCELLED    └──→ CANCELLED
```

允许的订单状态转换：

| 当前状态 | 允许目标状态 |
|---|---|
| `PAID` | `PROCESSING`、`CANCELLED` |
| `PROCESSING` | `SHIPPED`、`CANCELLED` |
| `SHIPPED` | `DELIVERED` |
| `DELIVERED` | 无 |
| `CANCELLED` | 无 |

退货和换货不会把订单状态直接改为“已退款”或“已换货”；它们创建独立售后申请。

## 4. 身份验证与权限

演示环境使用邮箱与演示验证码建立短期访问令牌。认证 HTTP 接口属于宿主应用边界，不导出为 Agent 工具；模型不得接触验证码或访问令牌。生产系统必须替换为真实 OTP、平台登录态或受信任的客户身份服务。

访问规则：

- 查看订单、物流、库存关联信息和创建工单前必须认证。
- 访问令牌只在服务端解析为客户身份。
- 即使用户正确提供另一个客户的订单号，也不能返回任何订单字段。
- 验证码、访问令牌和 Authorization Header 不得进入模型上下文或明文工具轨迹。

## 5. 取消订单

自动取消的必要条件：

- 订单属于当前客户；
- 状态为 `PAID` 或 `PROCESSING`；
- 审批仍在有效期内；
- 执行时订单版本与准备时一致；
- 宿主应用已记录与当前预览匹配的可信确认事件。

拒绝规则：

| 条件 | 原因码 | 处理 |
|---|---|---|
| 已取消 | `ORDER_ALREADY_CANCELLED` | 告知不可重复操作 |
| 已发货或已签收 | `ORDER_ALREADY_SHIPPED` | 提示签收后申请退货 |
| 状态不支持 | `INVALID_ACTION` | 不执行并转人工或说明 |

取消执行成功后：

- 订单状态变为 `CANCELLED`；
- 订单版本加 1；
- 保存唯一执行记录；
- 以数据库最终状态生成回复。

## 6. 自助退货

自动退货的必要条件：

- 订单状态为 `DELIVERED`；
- 签收后不超过 7 个自然日；
- 商品不是 `final sale`；
- 用户声明商品为 `NEW_UNWORN` 或 `OPENED_UNUSED`；
- 同一订单商品不存在处理中的退货或换货申请；
- 问题不是破损、瑕疵、错发或运输损坏。

v0 创建 `RETURN_REQUESTED` 记录，不直接退款。收货、验货、退款属于后续系统。

## 7. 尺码换货

除退货条件外，还必须满足：

- 用户明确目标尺码；
- 目标尺码与原尺码不同；
- 目标 SKU 与尺码当前库存大于 0；
- 执行阶段重新检查库存。

执行成功后预占 1 件目标尺码库存，并创建 `EXCHANGE_REQUESTED` 记录。若准备后库存被抢占，执行必须失败，不能产生负库存。

## 8. 强制转人工

以下情况不得由 Agent 自动认责、承诺赔偿或执行退款：

- 开胶、破损、瑕疵；
- 运输损坏；
- 错发商品；
- 已使用商品；
- 超期但用户提出特殊理由；
- 政策、订单或工具结果冲突；
- 用户要求高额赔偿或威胁投诉；
- 自动流程无法确定身份、商品或最终状态。

Agent 应创建工单，摘要只记录必要业务事实，不索取与处理无关的敏感信息。

## 9. 受控写操作

### 9.1 Prepare

`prepare_*` 负责：

- 重新读取订单；
- 调用确定性资格判断；
- 固化操作类型和参数；
- 保存订单版本；
- 生成对用户可见的操作预览；
- 对预览生成稳定的 `preview_hash`；
- 生成有时效的 `approval_id`。

它不修改订单、库存或售后申请。

同一客户和会话生成新审批时，旧的未完成审批进入 `SUPERSEDED`，不能继续展示或确认。

### 9.2 Present 与 Confirm

模型在拿到预览后只能解释并请求确认。宿主应用负责：

- 向用户展示完整结构化预览；
- 将审批从 `PREPARED` 转为 `PRESENTED`；
- 用户通过按钮或受控精确文本确认后写入 `ConfirmationEvent`；
- 将确认绑定到 `customer_id`、`conversation_id`、`approval_id`、`preview_hash`、`ui_event_id` 和确认来源；
- 使用不进入模型上下文的宿主确认凭据调用确认接口。

### 9.3 Execute

宿主应用触发的执行负责：

- 先检查 `approval_id` 属于当前客户和会话，再读取任何历史执行结果；
- 检查审批为 `CONFIRMED` 且未过期；
- 检查确认事件属于同一客户、会话、审批和预览；
- 检查订单版本没有变化；
- 重新运行资格判断；
- 执行业务写入；
- 消费确认事件；
- 读取并返回最终数据库状态。

`approval_id` 是“一份审批最多执行一次”的服务端幂等边界。客户端和模型不提交幂等键。

审批状态为：

```text
PREPARED → PRESENTED → CONFIRMED → EXECUTING → EXECUTED
```

终止或例外状态包括 `EXPIRED`、`SUPERSEDED`、`CANCELLED` 和 `FAILED`。

## 10. 错误码约定

| 错误码 | 含义 |
|---|---|
| `AUTHENTICATION_REQUIRED` | 工具需要认证 |
| `INVALID_CREDENTIALS` | 邮箱或验证码错误 |
| `TOKEN_EXPIRED` | 客户会话过期 |
| `CONVERSATION_REQUIRED` | 缺少宿主注入的会话标识 |
| `ORDER_NOT_FOUND` | 当前客户范围内未找到订单 |
| `ORDER_ITEM_NOT_FOUND` | 订单内无该商品 |
| `ORDER_ALREADY_SHIPPED` | 已发货，不可直接取消 |
| `RETURN_WINDOW_EXPIRED` | 超过自助售后期限 |
| `FINAL_SALE` | 特价排除商品 |
| `OUT_OF_STOCK` | 目标尺码无库存 |
| `HUMAN_REVIEW_REQUIRED` | 必须转人工 |
| `APPROVAL_NOT_PRESENTED` | 宿主尚未标记完整预览已展示 |
| `PREVIEW_MISMATCH` | 展示或确认的预览哈希不匹配 |
| `CONFIRMATION_NOT_FOUND` | 没有与审批绑定的可信确认事件 |
| `APPROVAL_EXPIRED` | 操作预览过期 |
| `APPROVAL_SUPERSEDED` | 新预览已取代该审批 |
| `STALE_APPROVAL` | 订单版本发生变化 |
| `WRITE_VERIFICATION_FAILED` | 写入后无法验证最终状态 |

## 11. v0 已知限制

- SQLite 不用于高并发生产写入；换货库存的并发锁定需要迁移到 PostgreSQL 后加强。
- 演示验证码是固定值，只用于本地运行。
- 政策检索当前为确定性关键词检索，不是语义向量检索。
- 写后验证发生在同一数据库事务中；生产环境应增加跨服务最终状态核验。
- 工具轨迹接口默认不注册；显式开启时仍需管理员令牌，且只返回安全字段。它不是安全审计。
- P0 改变了 SQLite 表结构，`create_all()` 不会迁移已有表；旧演示数据库必须先备份并重建。
