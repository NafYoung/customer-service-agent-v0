## 独立归因

34 个严格失败试验分成两类：

- 23 个是有效的模型或提示缺陷：冗余读取、缺参时先查询再澄清、未走权威资格工具、安全拒绝后没有继续完成正常请求，以及一次不真实的能力暗示。

仅作诊断的裁决后结果为 57 / 80（71.25%），pass^4 为 10 / 20（50.00%）。这个结果用于定位工程问题，不能替代正式成绩，也不能用于对外横向比较。

## Security 口径复核

原评分器把案例 `forbidden_tools` 中任何工具调用都计入 Security，包括用于约束效率的无害只读工具。因此 7 个“安全失败”实际都是对已认证客户本人订单的只读查询：

- 没有调用写工具；
- 没有泄露跨客户数据或凭据；
- 没有改变业务状态；
- 跨客户查询仍统一返回“未找到”。

安全关键口径下，本次是 80 / 80。原始 73 / 80（91.25%）仍保留在正式结果中，但不能解释成发生了 7 次安全事件。后续评分器应把“禁止的无害只读调用”归入 Tool selection 或 Efficiency，仅把写入、越权、敏感信息泄露和状态改变计入 Security。

## 可行动问题

有效失败的主要模式是：

1. 11 次在确定性资格判断前进行了冗余读取。
2. 6 次在信息不足时先读取订单，而不是直接询问最小缺失信息。
3. 2 次没有走资格判断的权威路由。
4. 3 次安全拒绝后停止，没有继续完成正常政策请求。
5. 1 次对不支持的地址修改暗示了不存在的记录能力；自动 Communication 分数没有捕捉到这一点。

这说明下一版需要同时改进提示路由和评分器，而不是只优化总分。

## 公开回归集

七个确认有效的失败模式已转为 `evals/readonly_regression_cases/` 下的公开开发回归案例。它们属于已退役 v1 的公开派生材料，不再是秘密 holdout，也不能用于重算或美化 v1 正式成绩。

等价工具路径和双政策检索上限没有进入回归集，因为原预期本身不成立。

## 后续门槛

1. 调整评分分类，分开安全关键违规与只读效率违规。
2. 对等价工具结果使用结果导向断言，不再强制单一路径。
3. 增加对虚假能力承诺的通信检查。
4. 修复提示和路由后，只运行公开开发回归。
5. 新的正式成绩必须使用独立策划、重新封存的 holdout v2；不得复用 v1。
